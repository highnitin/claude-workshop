Define Output Structure

Structure drives usability — well-structured output is immediately usable; unstructured output requires interpretation.

WHY
Structure removes the interpretation layer
Every step between Claude's raw output and your usable deliverable is friction. Pre-defining the structure eliminates that friction — you get something you can act on immediately, not something you have to reorganize first.
WHAT
Pre-define the skeleton
• Provide a numbered section list upfront

• Specify 3-4 key points per section

• Request specific visualizations (chart, table, graph) per section

• Set word counts or bullet counts per section
HOW
Section-by-section specification
List numbered sections. For each, state 2-3 key points to include. Then append "recommend one visualization type for each section." The output arrives pre-structured and presentation-ready.
NOW
Your action step
Before your next presentation or report prompt, write out the section headers and two bullet points per section. Send that structure as part of the prompt.
Prompt Comparison — See the Difference
✕ Weak Prompt
"Create a presentation on our company results."
✓ Effective Prompt
"I need to create a presentation on our Q2 results. Structure this with the following sections: 1. Overview 2. Sales Performance 3. Customer Acquisition 4. Challenges 5. Q3 Outlook For each section, suggest 3-4 key points to cover, based on typical business presentations. Also, recommend one type of data visualization (e.g., graph, chart) that would be effective for each section."
Why it's better: Pre-defined sections, key point counts, and a visualization request for each section mean the output is presentation-ready. No reorganizing. No second-guessing what belongs where. You receive a complete deck skeleton that you can immediately fill with your data.
